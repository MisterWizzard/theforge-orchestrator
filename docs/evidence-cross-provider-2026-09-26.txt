--- Defect found: the Codex critic had no shell (BLK-016) -----------------------------------
Codex's own words at the start of its critique: "The workspace shell is unavailable because its
sandbox cannot create a user namespace. I'll still audit the plan itself, but
repository-specific 'verified' claims remain independently unverified in this run."
The Codex CLI sandboxes itself (landlock/seccomp plus a user namespace) and cannot do so inside
TheForge's already-restricted container - non-root, read-only root filesystem, dropped
capabilities, no CAP_SYS_ADMIN. The critic therefore reviewed the plan text blind to the
repository, which is exactly why it raised finding #1 that the planner then refuted by looking.
Consequence: a Codex critic is materially weaker than a Claude one today, and any Codex stage
that needs to read files is degraded. Recorded as BLK-016; the likely fix is to tell the Codex
CLI not to sandbox itself, because the container already is the sandbox.
