## What this review found first

1. **CI on `main` has been red since PR #14 (`8d51928`).** Runs `36207611749` (`8d51928`), `36208474455` (`dd42aca`), `36210017715` (`e4068af`), `36211640304` (`b507535`) and `36213642655` (`b8b0ed8`) all fail the `quality` and both `portable` jobs; only `browser` passes. The same two tests fail every time: `packages/tier0/src/report.test.ts > writes a JSON array that parses back, and defaults under the outbox` (an assertion written against a Windows drive letter, `report.test.ts:92-94` at `b8b0ed8`) and `apps/coordinator/src/server.test.ts > routes under the ceiling: ...` (before PR #17: `pauses a run by guard ...`), which fails with `the planner job was never offered; run executing: run.created`. The session log entries for PRs #14–#18 say "merge on green CI (A3)"; the runs were not green. The local gates recorded in those entries (288/288, 375/376, 409/410) were true on this Windows host; they did not transfer to the hosted runners.
   - Root cause of the second failure, reproduced in this review on the same machine: the test starts a real pipeline run against the checkout itself (`repositoryUrl: process.cwd()`, `server.test.ts:930`), and `actions/checkout@v4` produces a depth-1 clone. A `git clone --bare --filter=blob:none` of a shallow repository (`packages/git-runtime/src/index.ts:195`) yields a cache with no refs (`warning: rejected ... because shallow roots are not allowed to be updated`), and the run then sits at `run.created` past the test's 30 s deadline. From a shallow clone of this worktree the test fails identically in 30.1 s; from a full clone it passes in 2.8 s (both 26/09/2026, `DATABASE_URL` set).
   - Fixed here: the Tier 0 assertion is platform-neutral (`report.test.ts:92-98`), and `.github/workflows/ci.yml` checks out with `fetch-depth: 0` in the `quality` and `portable` jobs. Both fixes are verified locally, **not** in CI, because this review does not push. The first CI run after the merge is the evidence.
   - Open: a pipeline whose bare cache has no refs should fail fast with the git error rather than sit until the worker-job wait expires; that is a robustness finding, not a security one.
2. **`C:\forge` is readable by every local account** (`BUILTIN\Users:(RX)`, `Authenticated Users:(M)`, icacls 26/09/2026), including `.env`, retained workspaces, the outbox and the halt file. Operator action; threat model T10.
3. **Tier 0 runs untrusted dependency code on the host** as the operator with the `gh` CLI's `repo`-scope token (`packages/tier0/src/runner.ts:198-260`). Contained by the two-repository allowlist; threat model T11.
4. **The web BFF authenticates nothing itself** and `pnpm dev` bound Next.js on all interfaces; `next dev` now binds `127.0.0.1` (`apps/web/package.json:6`). Threat model T15.
5. Bearer tokens were compared with `!==`; now `secretEquals` (constant time) in `packages/policy` with a test, used at every coordinator check.
6. Fifteen coordinator and worker variables had no specific remedy in the fail-fast table; added, with a test that every schema variable has one (`tests/env-example.test.ts`).
7. Six dev-only dependency advisories were fixable by patch-level overrides and are fixed; three are accepted with reasons (`docs/evidence-dependency-audit-2026-09-26.txt`). Production audit clean before and after.
